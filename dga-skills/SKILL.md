# DGA SKILLS TOOLKIT (`dga-skills`) — orchestration + LIVE DGA fidelity + Design Modes + DGA packages/icons/adapters

> Created and developed by Ahmed Darwish. Independent project — not affiliated with, endorsed by, or certified by the Saudi Digital Government Authority (DGA). "DGA" here names the design system being followed, never an approval. A legacy install named `ahmed-skills` is migrated automatically by the installer; a legacy `.claude/ahmed-skills.json` is read and migrated to `.claude/dga-skills.json`.

## 0. Session start (do this before anything else)
0. **Where this skill runs** — every file it needs (rules, `references/dga-live`, registries, patterns, templates, `lib/`, tools) is inside this skill's own folder, `${CLAUDE_SKILL_DIR}` (paths below are relative to it; in the other files of this folder `${CLAUDE_SKILL_DIR}` means this same folder). This holds for a global Claude Code install, a project install, and a skill uploaded to Claude Desktop / Cowork / claude.ai as a ZIP. **Never ask the user to upload or paste SKILL.md, the references or the registries** — open them from this folder. If a script cannot run (no Python in the sandbox), read the same data files directly and say so. Run every tool as its own standalone command (`python3 ${CLAUDE_SKILL_DIR}/tools/<tool>.py …`) — no `VAR=…;` prefixes, `&&` chains or pipes — so Claude Code can approve it with one prompt or one `Bash(python3:*)` rule.
1. **Onboarding gate** — `rules/onboarding.md`. If the task creates or substantially changes UI: read `<project>/.claude/dga-skills.json` (legacy `.claude/ahmed-skills.json` is migrated by the tool) (`python3 ${CLAUDE_SKILL_DIR}/tools/project_settings.py get --project <root>`).
   - Saved → announce the one-line settings summary and continue; never re-ask.
   - Missing → **ask ONLY the Design Mode question** (DGA Exact / DGA Enhanced / DGA Creative) and **end the turn**. Do not list the technology options in that message, even if you can guess the stack. **Next turn: ask Technology** (React / Angular / ArcGIS Experience Builder / Other / Auto Detect) — you may suggest the detected stack there. Then save with `project_settings.py set` (one standalone command; never Edit/Write the settings file). Do not write UI code before both answers.
   - Minor edits, questions, reviews, non-UI work → do not ask (`rules/onboarding.md` §5).
2. **Mode rules and QA gates** — `rules/design-modes.md`. Never claim DGA Exact compliance without the evidence that mode requires.
3. **Policies** — `rules/policies.md` (icons: `@platformscode/icons` primary, mapped Hugeicons Free fallback; real DGA packages preferred over CSS recreations; `platformscode-new-react@0.1.45` official publisher status NOT VERIFIED).
4. **Optional helpers (Zero-Manual-Dependency-Setup)** — UI/UX Pro Max and Frontend Design make Enhanced/Creative research richer; the toolkit never needs them and the user never has to set them up by hand. For every design, redesign, art-direction, motion or Creative/Enhanced task run `python3 ${CLAUDE_SKILL_DIR}/tools/deps.py status` (offline, read-only; it sees Claude Code plugins, user/project skills, and skills synced by Claude Desktop / Cowork in `skills/synced/`) and treat the session's own skill list as the final authority (`frontend-design:frontend-design`, `ui-ux-pro-max:ui-ux-pro-max`, or the host names `frontend-design`, `ui-ux-pro-max`, `anthropic-skills:…`). Copy the result lines into the reply and **carry out every `→` line it prints, exactly and in this turn** (`USE NOW` = invoke that skill and run its script; `NEXT` = run that command yourself). "Installed" ≠ "invoked": only claim invocation after you actually called the skill.
   - **Available → use it automatically**: in Enhanced/Creative design work invoke EVERY available helper with the Skill tool (and run `ui-ux-pro-max`'s `search.py`) before choosing a direction, and record the call — a short or text-only request is not a reason to skip one.
   - **Missing in Claude Code** (`environment: claude-code`) → run `python3 ${CLAUDE_SKILL_DIR}/tools/deps.py ensure` once (no question to the user: it installs only from the verified official marketplaces, after a source + licence check, records the run, and does not retry a recent failure). Claude Code's own permission prompt for that command is the only approval. New plugins load in the next session (`/reload-plugins`), so continue THIS task with the local fallback and say so in one line.
   - **INSTALLED BUT DISABLED** → the user turned it off: respect that, use the fallback, mention it once (never re-enable it yourself).
   - **Missing in Claude Desktop / Cowork** (`environment: claude-desktop-cowork`, state `NOT AVAILABLE IN THIS SESSION`) → platform limit: a skill cannot install or turn on other skills there. Do NOT ask the user to install, upload or configure anything; continue with the local fallback (`rules/design-intelligence.md`, `rules/art-direction.md`) and write one informational line: `Optional helper <name>: not available in this session → built-in fallback used.`
   - Knowledge-base integrity: `tools/registry_integrity.py` (210 sets / 10,499 variants / 20 templates).
5. **DGA packages, icons and code** — `rules/package-integration.md`. Before generating any component: `tools/find_existing.py` (reuse first). Library code only via `tools/copy_lib.py` (`lib/` core + React / Angular / vanilla / ExB adapters, see `adapters/*.md`). Props only from `registry/packages/platformscode-core@<installed>.json`; check with `tools/check_dga_props.py`. Known defects and workarounds: `registry/packages.json` (cite PKG-… IDs). Icons: `registry/icons/icon-map.json`, one central registration, `@platformscode/icons` primary, Hugeicons Free fallback.
5a. **Home / landing / portal pages and their inner pages** — follow `patterns/home-page.md` section by section; a **service details** page follows `patterns/service-page.md` and a **services list / catalogue** follows `patterns/services-page.md` (header actions icon+text, «عرض الكل» outline buttons, figures = template composition not Metric, services card carousel with tags + two actions, partners strip, «تاريخ آخر تعديل», template footer). Do not improvise these sections.
5b. **Patterns, templates and Visual QA** — `patterns/README.md` (header, hero, section heading, cards/grids, stats, forms/filters, footer) and `lib/templates/templates-map.json` (all 20 DGA templates; Home / Service / Form / FAQ / 404 have executable React + vanilla(+Angular) code). Copy with `tools/copy_lib.py --framework <fw> --dest <dir> --with-patterns`; compose from the real DGA components only, every custom composition carries `data-house` and is labelled `[AHMED HOUSE]`, never "certified DGA". Before claiming any gate: run the engine `node ${CLAUDE_SKILL_DIR}/tools/qa/run.mjs --config qa.config.json` (`tools/qa/README.md`) on real pages — it measures E2–E6, N2–N5, C4, axe, keyboard, overflow at 1440/1024/768/390 RTL+LTR, reduced motion and component states against `references/dga-live/data`; E1, N1, C1–C3, C5 stay **REVIEW REQUIRED** (never auto-PASS). Paste the verdict line of `REPORT.md` into the reply. A failing required component (package or not) means **DGA Exact is NOT compliant** — say so with the PKG-… ID; never patch `node_modules`, never recreate an unsupported state in CSS. Icon shape fidelity: `tools/qa/icon-fidelity.mjs` (`registry/icons/icon-map.json` → `verification.shape`, name coverage ≠ visual similarity).
6. **Hard stops for code in a project (always, in this order — record each in the reply):**
   a. `python3 ${CLAUDE_SKILL_DIR}/tools/find_existing.py --project <root>` → follow its DECISION lines (reuse what exists).
   b. Before using a prop/state, look it up in `registry/packages/platformscode-core@<installed>.json` (`registry/packages.json` for defects). If the request needs something the installed API does not have (e.g. Button Selected/toggle — PKG-BTN-03): **STOP. Write no code.** Explain the gap with the PKG ID and ask the user to choose: leave it out / approve a labelled `[AHMED HOUSE]` extension / wait for a package version. In DGA Exact mode a house extension is never the default. Never create a new wrapper or restyle a DGA component without that explicit approval (shadow DOM: page CSS cannot style component internals).
   c. Icons: look the name up in `registry/icons/icon-map.json` and state its status (both / platformscode-only / missing, Style); add it to the ONE existing registration.
   d. After writing code: `python3 ${CLAUDE_SKILL_DIR}/tools/check_dga_props.py --project <root>` must say `OK — no invented props`.
   e. Site-level consistency + Clean Code: one site configuration (`lib/site/site-config.js`) and one shared header/footer for every page — pages never change menu order, sub-menus or footer variant; DRY, full descriptive names (`camelCase` / `PascalCase` / `UPPER_SNAKE_CASE`) and per-technology structure from `rules/code-quality.md`. Before reporting, run `python3 ${CLAUDE_SKILL_DIR}/tools/code_quality_check.py --path <project src>` and fix every finding (it enforces those rules; exit 1 = not done).
7. Everything below still applies in full.

**Read first**: `rules/onboarding.md`, `rules/design-modes.md`, `rules/package-integration.md`, `rules/orchestration.md`, `rules/upstream-queries.md`, `rules/design-intelligence.md`, `rules/art-direction.md`, `rules/motion-engineering.md`, `rules/dga-guard.md`, `rules/visual-qa.md`, `rules/project-detection.md`, `rules/component-contract.md`. ## Native specialist integration (discovery rules: `rules/orchestration.md`)
1. `ui-ux-pro-max`: available if `tools/deps.py status` reports it (Claude Code plugin `ui-ux-pro-max@ui-ux-pro-max-skill`, a user/project `skills/ui-ux-pro-max`, a skill synced by Claude Desktop / Cowork, or a host-provided skill) or the session lists `ui-ux-pro-max:ui-ux-pro-max`; verify its scripts run, INVOKE the skill with the Skill tool AND RUN `search.py` / `design_system.py` with subject-specific queries from `rules/upstream-queries.md` (pattern, style, motion, stack). Record each query, result count and on/off-target verdict. Never describe output you did not run. If missing, use `rules/design-intelligence.md` and flag `UPSTREAM_UIUX_NOT_INSTALLED`.
2. `frontend-design`: the official Anthropic plugin **`frontend-design:frontend-design`** counts as installed; a local `.claude/skills/frontend-design/SKILL.md` is optional and NOT required. INVOKE it with the Skill tool for visual personality, typography/composition and anti-template critique. If neither source exists, use `rules/art-direction.md` scorecard and flag `UPSTREAM_FRONTEND_NOT_INSTALLED`.
3. DGA LIVE reference at `references/dga-live/` (all 24 DGA Platforms Code files: every variant, state, token and prototype motion) is the **source of truth for UI chrome**, read-only. Upstream fonts, hex palettes and component tokens NEVER override it; quote them as "[UPSTREAM DESIGN ADVICE — rejected for UI chrome]". Anything absent is **UNKNOWN** or **[AHMED HOUSE]** (see `rules/dga-guard.md`), never invented.
4. Arabic RTL requirements are enforced by Ahmed rules (`rules/art-direction.md` RTL section) because upstream datasets contain no RTL guidance.
5. Motion/3D is our engineered house layer: see `rules/motion-engineering.md`. GSAP, ScrollTrigger or three.js only if actually in dependencies or explicitly authorized; media asset existence, dimensions and licensing verified first.

## Work algorithm (required)
A. DISCOVER: read project/route, assets, components, design-system packages, user task and target audience. Record actual sources and data limitations.
B. RESEARCH: call available specialist skills; extract at least 3 contrasting *composition/narrative* options (not 3 palettes).
C. DIRECT: one powerful purpose-driven art direction with a visual signature linked to project subject. For each option provide a 1-sentence concept, focal point, section geometry, imagery strategy and motion consequence.
D. PROTOTYPE: produce browser-viewable isolated proof / 3 annotated screenshots for materially different options; use real project media where permitted. Never start major production changes from prose-only spec if visual excellence is the stated goal.
E. JUDGE: score each option with `rules/visual-qa.md`. Reject generic hero, repetitive card grid, weak imagery, lost hierarchy. Validate against DGA. Record why winner won.
F. IMPLEMENT: user-approved concept in a rollback-safe feature branch/checkpoint, progressive enhancement, semantic content, RTL/LTR, performance, GIS preservation. If auto-execution authorized, proceed section by section and independently audit each.
G. PROVE: actual browser screenshots at 1440/1024/768/390; capture evidence of RTL, LTR, keyboard, reduced-motion, 200% zoom, landscape and scrolling; verify functionality; typecheck/build/lint. If unable, mark pending instead of claiming passed.

## Release gate
Do not say "done" unless the candidate meets visual, system, interaction, content, accessibility and performance gates. Design excellence cannot be proved by TypeScript passing. Use the evidence sheet in `templates/visual-approval.md` and checklist `rules/visual-qa.md`.

## DGA component requests — "اعمل dropdown / زرار / tabs …" (mandatory)
When the user asks for any DGA component, it must come out **typical to the Figma component**: same variants, same states with the same values, same anatomy, same motion.
1. `references/dga-live/INDEX.md` → open the component spec (web unless the target is a native/mobile app).
2. Follow `rules/component-contract.md` exactly: Properties → Anatomy → State changes → Interactions & motion; build the state table with citations.
3. Tokens only from `foundations/dga-tokens.css`. Motion only from the spec (`INSTANT` = none; e.g. Dropdown open = SMART_ANIMATE 150ms EASE_OUT). Add `prefers-reduced-motion` fallback.
4. Composite components reuse their sub-components' specs (Dropdown uses Dropdown List Item + Checkbox; Pagination uses Dropdown List Item; Toast uses Button-Close…) — check the instances named in the anatomy.
5. Prove it: screenshot every state (incl. RTL, focus-visible, disabled, error) next to the Figma variant link at the top of the spec.
